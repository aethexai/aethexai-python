# Contributing to aethexai

Thanks for your interest in improving the official Python SDK for Aethex. This guide covers the
day-to-day workflow. If anything here is unclear or out of date, open an issue.

## Getting started

We use [uv](https://docs.astral.sh/uv/) for dependency management. Install it, then:

```bash
git clone https://github.com/aethexai/aethexai-python.git
cd aethexai-python
uv sync --all-extras --dev
```

That installs every runtime dependency, the optional `realtime` extra, and the dev tooling
(pytest, respx, ruff, mypy). If you don't intend to touch the WebRTC code, you can skip the
`realtime` extra (it pulls in `aiortc`, `aioice`, and `av`):

```bash
uv sync --extra dev
```

## Running tests

The default suite uses `respx` to mock HTTP and runs in a few seconds:

```bash
uv run pytest
```

Scope it with markers:

```bash
uv run pytest -m "not integration"   # default — pure unit tests
uv run pytest -m integration         # hits the live API, requires AETHEX_API_KEY
uv run pytest -m slow                # longer-running tests
```

Integration tests look for `AETHEX_API_KEY` in the environment and hit `https://api.aethexai.com`.
Without a key they are skipped. Run a single file or test with:

```bash
uv run pytest tests/test_kora_methods.py
uv run pytest tests/test_kora_methods.py::test_kora_list_voices
```

## Lint, format, and types

Ruff handles linting and formatting; mypy handles type-checking. Run before pushing:

```bash
uv run ruff check .
uv run ruff format .
uv run mypy src/aethexai
```

Configuration lives in `pyproject.toml`. The generated client (`src/aethexai/_generated/`) is
excluded from both ruff and mypy — don't lint it or edit it by hand (see below).

## Pre-commit

A pre-commit config is included. Enable the hooks once:

```bash
uv run pre-commit install
```

They run `ruff` (with `--fix`) and `ruff-format` plus basic file-hygiene checks on staged files.

## Generated vs hand-written code

You only edit the **hand-written** client code:

- `client.py`, `_async_client.py`, `kora.py`
- `realtime/`, `_exceptions.py`, `_body.py`, `__init__.py`

The HTTP layer under `src/aethexai/_generated/` is produced by
[openapi-python-client](https://github.com/openapi-generators/openapi-python-client) from the
Aethex OpenAPI spec and is **regenerated by maintainers** — never edit it by hand, since it is
overwritten on the next regeneration. If something there is wrong, fix it in the hand-written
wrapper that calls it, or open an issue.

`AethexAI` and `AsyncAethexAI` are kept method-for-method identical; if you add a method to one,
add it to the other (parity is enforced by `tests/test_async_parity.py`).

## Pull requests

- Branch from `main` with a descriptive prefix — `feat/`, `fix/`, `chore/`, `docs/`, `refactor/`.
- One logical change per PR.
- Add at least one unit test under `tests/` for any new client method.
- Update `CHANGELOG.md` under `## [Unreleased]` for anything user-facing.
- Explain *why* in the description; reviewers can read the diff for the *what*.

## Release process (maintainers)

Releases are tag-driven; the `release.yml` workflow builds and publishes to PyPI via Trusted
Publishing. To cut a release:

1. Bump the version in `src/aethexai/_version.py` and `pyproject.toml`.
2. Move the `## [Unreleased]` CHANGELOG entries under the new version heading.
3. Commit, push to `main`, then tag and push:

```bash
git tag -a vX.Y.Z -m "Release X.Y.Z"
git push origin vX.Y.Z
```

Don't upload manually — Trusted Publishing is configured for the workflow, not individual accounts.

## Contact
